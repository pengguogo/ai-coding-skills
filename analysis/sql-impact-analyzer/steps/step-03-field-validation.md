# Step 3: 订正字段合理性分析

## 元信息

- execution-mode: inline

## 参数

- input: Step 1 的 SQL 解析结果 + Step 2 的 Entity 定义
- output: 字段合理性分析表

## 执行指令

对每条订正 SQL 涉及的 SET 字段，进行以下维度的合理性分析：

### 1. 字段类型与值类型一致性

| 检查项 | 说明 | 验证方式 |
|--------|------|---------|
| 类型匹配 | SET 值与字段声明的 Java 类型是否兼容 | 查看 Entity 定义中字段的 Java 类型 |
| 长度匹配 | SET 值长度是否超过字段定义长度 | 查看 DDL 中 VARCHAR(len)/DECIMAL(precision,scale) |
| 枚举匹配 | SET 值是否在字段定义的枚举范围内 | 查看代码中状态常量或枚举定义 |
| NULL 约束 | 字段是否有 NOT NULL 约束，SET NULL 是否合理 | 查看 DDL 和 Entity @Column 注解 |

### 2. 业务合理值范围

对每个字段分析业务层面的合理取值：

| 维度 | 示例 |
|------|------|
| 金额字段 | 是否 ≥ 0？是否有上限（如本金不超过贷款金额）？ |
| 日期字段 | 是否在合理时间范围内（当前±N天）？是否为工作日？ |
| 状态字段 | 目标值是否是合法业务状态流转？（如未到期→已结清，跳过中间状态） |
| 利率字段 | 是否在合理区间（如 0.01~0.36）？ |
| 计数/期次字段 | 是否 ≥ 当前值？是否 ≤ 总期数？ |

### 3. 字段依赖一致性

检查 SET 字段值之间是否存在逻辑矛盾：

| 检查项 | 示例 |
|--------|------|
| 金额合计 | 本金 + 利息 + 罚息 = 应还总额？ |
| 日期先后 | start_date ≤ end_date？next_cycle_date > last_cycle_date？ |
| 状态联动 | 状态改为"已结清"但余额 > 0？ |
| 期次对应 | 期次序号与日期是否对应？（如第3期应对应第3个月的日期） |

### 4. WHERE 条件覆盖风险

分析 WHERE 条件的精确度：

| 检查项 | 风险 |
|--------|------|
| 仅用 single key 匹配 | ✅ 确定唯一记录 |
| 使用范围条件（BETWEEN、<、>） | ⚠️ 可能匹配多条记录 |
| 无完整主键 | ⚠️ 可能误改 |
| 使用 LIKE 模糊匹配 | ❌ 高风险误改 |
