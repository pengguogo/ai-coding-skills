# Step 8: 质量校验（Subagent Check）

## 元信息

- execution-mode: subagent
- agent: general-task-execution
- checkpoint: checkpoints/step-08-checkpoint.md

## 参数

- input: Step 1-7 的全部产出
- output: 质量校验结果

## 执行指令

使用 `invokeSubAgent`（name: `general-task-execution`）执行交叉校验。

### Subagent Prompt 模板

```
请对以下数据变更影响分析结果进行质量校验。你是独立审查者，必须重新验证所有事实源引用。

## 校验输入

[将 Step 1-5 的完整产出粘贴到此处]

## 校验项

### 1. 完整性检查
- 每个被修改的字段是否都有对应的后置功能分析？
- 是否有遗漏的 EOD Job 或在线交易？
- 使用 grepSearch 搜索目标字段名，确认没有遗漏的 Mapper XML 引用

### 2. 事实源验证
- 报告中引用的代码文件路径是否真实存在？（使用 readFile 验证关键路径）
- 引用的行号处的代码内容是否与报告描述一致？
- SQL 条件是否与 Mapper XML 原文一致？

### 3. 逻辑一致性
- 风险等级判定是否与影响说明匹配？
- P0 级风险是否确实会导致资金/出单层面的问题？
- 后置功能的触发条件描述是否准确反映代码逻辑？

### 4. WHERE 条件覆盖
- 订正 SQL 的 WHERE 条件是否可能影响到非目标记录？
- 是否建议执行前先 SELECT COUNT(*) 确认影响行数？

### 5. 时序依赖
- 多条 SQL 之间是否存在执行顺序依赖？
- 先后顺序是否会影响最终结果？

## 输出格式

对每个校验项输出：
- ✅ [校验项] - 通过原因
- ❌ [校验项] - 问题描述 + 具体修正建议（须指明哪个 Step 的哪个产出需要修正）
- ⚠️ [校验项] - 报告中未覆盖但应补充的内容

## 校验原则

- 必须实际读取代码文件验证，不可凭记忆判断
- 对文件路径使用 readFile 确认存在性
- 对关键 SQL 条件使用 grepSearch 确认原文
```

### 校验后处理

1. **全部 ✅**：进入 Step 9
2. **存在 ❌**：根据修正建议回到对应 Step 修正，修正后重新执行 Step 5
3. **仅有 ⚠️**：将补充建议纳入 Step 6/7 产出后进入 Step 9
4. **最多重试 2 次**：如果 2 次校验后仍有 ❌，将未解决项标注为 `[需人工确认]` 后进入 Step 9

## 产出

- 质量校验结果（✅/❌/⚠️ 清单）
- 修正动作记录（若有）
