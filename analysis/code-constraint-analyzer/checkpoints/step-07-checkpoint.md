# Checkpoint: Step 5 分析归类校验

> **审查级别**：L2（深度审查）— 需验证分类正确性与分级合理性。
> **审查原则**：你是审查者，不信任前置步骤的初分结果。重新打开源文件核对每条高风险项。

## 校验清单

### 分桶正确性
- [ ] 每条发现被正确分配到对应场景桶（deadcode / redundant / duplicate）
- [ ] 无跨场景混淆（如冗余代码被标为重复代码）
- [ ] 风险二次评级有明确理由

### 数据一致性
- [ ] 三份扫描产出的发现总数 = 分桶后的发现总数
- [ ] 拆分策略合理（单桶 ≤ 20 条，超过则按模块拆）
- [ ] 每条发现保留原始来源标注（Step 2/3/4 的产出 ID）

### 分级合理性
- [ ] high 级别抽查 5 条（确认影响链路上的代码）
- [ ] medium 级别抽查 3 条（确认不是漏报的 high）
- [ ] 分级标准一致（同类型发现分级无矛盾）

## 判定标准

- **全部 ✅**：进入 Step 6 方案设计
- **存在 ❌**：修正分级后重新校验，最多重试 2 次
- **仅 ⚠️**：标注后进入 Step 6
