# Step 7: 质量校验

## 元信息

- execution-mode: subagent
- agent: scan-verifier
- checkpoint: checkpoints/step-07-checkpoint.md
- checkpoint-level: L2

## 参数

- input: Step 2-6 的全部产出
- output: 校验结果清单（✅/❌/⚠️ + 修正动作）

## 目的

由独立 subagent 重新验证所有发现，确保报告可交付：事实源真实、分级合理、无漏检。

## 执行指令

### 1. 事实源验证（交叉抽样）

从 Step 2/3/4 中随机抽样 30%（最少 10 条），逐条打开源文件核对：
- 行号是否准确
- 代码片段是否真实存在（未被后续提交修改）

若发现假阳性 → 标记 ❌，从报告中移除该项。

### 2. 分类与分级合理性

- 无效代码：入口可达性判断是否正确（抽样 5 条验证调用链）
- 冗余代码：N+1 判定是否准确（确认循环体内确实有 DB 调用）
- 重复代码：相似度阈值是否合理（抽样验证 3 对代码块）

### 3. 覆盖率检查

- 扫描范围是否覆盖了 Step 1 确认的全部模块
- 排除目录是否被正确排除
- 入口层清单是否完整（至少每个模块找到 1 个入口组件）

### 4. 方案可行性

- high 级别项是否有 before/after 代码
- 方案是否引入新问题（如批量查询可能导致内存溢出）
- 单测 case 是否覆盖边界条件

### 5. 输出

```markdown
# 质量校验报告

## 事实源验证
- 抽样：{N} 条
- 通过：{N} 条
- 假阳性（已移除）：{N} 条

## 分级合理性
- 上调：{N} 条
- 下调：{N} 条

## 漏检补充
- 补充发现：{N} 条

## 方案可行性
- 通过：{N} 项
- 需修正：{N} 项

## 校验结论
{通过 / 有条件通过 / 不通过}
```

## 产出

- 质量校验报告（`upgrade/{scene}_{date}/_workspace/code-constraint/quality-check-report.md`）
