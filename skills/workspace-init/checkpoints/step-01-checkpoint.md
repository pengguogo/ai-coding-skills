# Checkpoint: Step 1 清单解析

> **审查级别**：L1（轻量审查）— 只检查结构和内容维度。
> **审查原则**：确认 repos.txt 已被正确解析，所有格式问题已被发现并报告。必须重新打开产出文件逐项核对，不能凭记忆判断。

## 审查时需打开的文件
- 审查对象：控制台输出中的结构化清单
- 上游比对：`repos.txt`

## 结构检查
- [ ] repos.txt 文件存在且已读取
- [ ] 所有有效数据行已解析为结构化清单（行数与 repos.txt 中非空非注释行一致）
- [ ] 汇总数字正确（有效行 + 错误行 = 总非空非注释行）

## 内容检查
- [ ] 每行的 name 非空且无重复
- [ ] 每行的 type 为 app 或 kb
- [ ] 每行的 url 以 http:// 或 https:// 开头
- [ ] branch 为空的行已标注默认分支策略
- [ ] 格式错误行已标注行号和具体原因

## 待确认项提取
- 若 repos.txt 不存在 → 提取为 BLOCKED 项
- 若有格式错误行 → 提取为待用户确认项（是否忽略错误行继续执行）
