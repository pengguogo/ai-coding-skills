## 执行指令

按 01-source-inventory.md 的推导索引表和页面角色矩阵，逐模块摘录规则：

### 1. 摘录原则

- 对驱动行为的规则**引用原文或紧贴原文转述**；评审需要时可记控件 id 或页面 id
- **表格**：若表达状态机、权重、映射，转为 Markdown 表收录
- **HTML 可见性**：凡节点（含祖先）呈现 `display:none` 或 `visibility:hidden` 的，一律忽略
- **纯图流程**：记「无结构化文字，需视觉评审」

### 2. 重点规则优先摘录

优先于背景说明、愿景描述摘录以下内容：
- 入口规则：从哪里进入、谁可见、什么状态下显示、按钮是否置灰/禁用
- 触发规则：点击、提交、切换、审核、超时、自动处理等触发条件
- 类型与枚举：申请类型、状态枚举、原因枚举、字段选项
- 表单规则：必填项、默认值、只读项、互斥关系、条件必填、上传限制
- 结果规则：提交后是否生成单据、是否翻转状态、是否需要审核
- 时效规则：X 天、超时自动通过、超时禁用、时限内仅支持一次
- 展示规则：列表字段、详情展示块、分组展示
- 角色与端差异：不同角色/端在同一规则下的差异口径

### 3. 描述粒度要求

规则描述至少包含：
- 场景/前提：在哪个页面、哪个状态、哪个角色下成立
- 动作/条件：用户做了什么，或系统在什么条件下触发
- 约束：字段、枚举、次数、时效、可见性、数量限制
- 结果：状态如何变化、是否生成记录、是否跳转、是否提示

推荐句式：「谁在什么页面/状态下，执行什么动作，满足什么约束后，会得到什么结果。」

### 4. 复杂模块深扫

若某模块同时具备总表/总述页、多个状态页、列表/详情/动作页、后管页：
- 先按页面角色矩阵逐页扫描
- 主规则页给出汇总口径时，状态页和动作页必须继续逐页检索
- 列表/详情/操作页除字段外，还要记录入口来源、筛选项、按钮显示条件、按钮结果、跳转目标、状态变化
- 后管页必须分别判断是导航占位还是真正承载规则的页面
- 纯图页与无可见文本页必须显式写出"仅视觉参考"或"无可见规则文本"

### 5. 产出格式

按模块组织，每个模块包含：
- 来源分层与可见性说明
- 规则摘录（按重要规则卡片或规则句格式）
- 待澄清问题

不臆造原型中不存在的功能。缺失信息标注 `[需与产品确认]`。
