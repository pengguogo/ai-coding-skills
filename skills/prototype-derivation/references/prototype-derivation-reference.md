# 原型推导 — 参考手册

与 [SKILL.md](../SKILL.md) 配合使用：在需要细化操作步骤、模板或 Axure/HTML 习惯时阅读本文。

---

## 1. Axure 导出 HTML 常见结构（通用）

| 元素 | 说明 |
|------|------|
| \`start.html\` | 入口，内嵌或跳转至各页。 |
| \`data/document.js\` | 常含站点地图、页面列表；用于模块边界与废弃节点。 |
| \`files/<页面名>/\` | 单页资源与 \`data.js\`。 |
| \`#u数字\` | 常见控件 id；文本多在 \`#u*_text\` 的 \`<p><span>\` 内。 |
| \`display:none\` / \`visibility:hidden\` | **一律跳过**，不摘录、不生成需求；含 Axure 默认未展开的面板 state。 |
| 动态面板 \`panel_state\` | 仅**默认可见** state 参与摘录；其余 state 若在 HTML 中为隐藏，**不**自动纳入；若业务需要多状态，以产品指定可见稿或单独说明为准。 |

## 2. 来源盘点检查清单

- [ ] 已打开或检索**站点图**来源（\`document.js\` 或等价物）。
- [ ] 已记录**本期范围**依据（总述页、需求清单 HTML、口头范围——以后者为准时需用户确认）。
- [ ] 已列出**废弃/忽略**节点及原因。

- [ ] 已确认**未**将 \`display:none\` / \`visibility:hidden\` 节点内容写入推导或需求。

## 3. 文本与表格摘录要点

- **原文优先**：业务规则、数值区间、枚举值尽量与原型一致；明显笔误可「原文照录 + 括号注明疑误」。
- **表格**：状态×动作、三方映射、权重分配等，**整表迁入**推导明细或附件，避免只写「见某表」而无内容。
- **多版本同页**：同一 HTML 内两段并列规则（如「版本 A / 版本 B」）→ 分别标注块位置或序号，并进入**冲突日志**（若互斥）。

### 3.1 重点规则摘录清单

遇到以下内容，优先于背景说明、愿景描述、页面装饰语摘录：

- **状态机类**：状态总表、状态映射、状态切换条件、状态终态。
- **操作类**：申请、撤销、审核、拒绝、同意、提交、取消、平台介入、自动处理。
- **表单类**：字段、必填、默认值、联动项、条件必填、上传附件/图片、字数限制。
- **列表类**：Tab、筛选项、排序、字段列、操作列、空态/无数据提示。
- **时效类**：有效期、超时、自动审核、按钮禁用时间点、次数限制。
- **结果类**：是否生成单据、是否进入列表、是否更新订单状态、是否更新商品状态、是否提示成功/失败。
- **多角色差异类**：调货商/供应商/后管、PC/H5/后台之间的差异规则。

### 3.2 推荐描述句式

建议将原型规则整理为可复用的“规则句”，而不是只记零散关键词。可直接套用：

\`\`\`markdown
- 在 \`<页面/块>\` 中，\`<角色>\` 于 \`<状态/前提>\` 下点击 \`<按钮/入口>\`，需满足 \`<条件/字段约束>\`；提交后 \`<结果/状态变化/跳转/提示>\`。
\`\`\`

示例：

\`\`\`markdown
- 在 \`待商家接单状态.html\` 中，调货商在订单状态为“待商家接单”时点击【取消订单】，原因必填，选择“其他”时补充原因描述必填；提交后无需审核，订单状态直接变为“已取消”，且不生成售后单。
\`\`\`

### 3.3 推荐“规则卡片”记录法

对于重要规则，推导明细中可按下表摘录，便于后续写 REQ/测试：

\`\`\`markdown
| 规则项 | 内容 |
|--------|------|
| 来源页 | \`待商家发货状态.html\` |
| 适用角色 | 调货商 |
| 适用前提 | 订单处于待商家发货；部分商品已发货 |
| 触发动作 | 点击申请售后 |
| 约束/字段 | 已发货商品支持退货退款/换货/仅退款；原因必填；支持上传最多 3 张照片 |
| 结果 | 生成售后单；商品状态变为售后处理中；订单状态不翻转；进入供应商审核 |
\`\`\`

若同一页存在多条重要规则，建议拆成多张规则卡，而不是混成一段长摘要。

## 4. 冲突 / 决策日志（模板）

复制使用：

\`\`\`markdown
| 编号 | 主题 | 来源 A（页/块） | 摘要 A | 来源 B（页/块） | 摘要 B | 建议确认问题 |
|------|------|-----------------|--------|-----------------|--------|--------------|
| C01 | （如：有效 OE 长度） | | | | | |
\`\`\`

- **不要**在日志里写「已采用 B」除非用户/产品已明确表态。
- 建议问题应**可回答**（是/否、选 A 或 B、或分端策略）。

## 6. 纯图、流程图、接口示意图

- 推导明细中记：**无结构化文本**、所在页面或文件名（由用户给出）、**建议评审会确认**的结论类型（步骤顺序、异常分支等）。
- 若图中数字与某页文字规则**冲突**，按**冲突日志**处理，不擅自取舍。

## 8. 笔误与命名（常见）

在推导稿中可单列「**待统一**」，示例：

- 同一数据域多种叫法（如「后管-总仓」与「-总仓」）。
- 明显错别字（如「再/在」「说说明」）。
- 英文大小写混用的专有名词。

不在未确认时强行统一进「正式规则句」，只记录选项。

## 9. 非 Axure 原型

- **Figma / 在线文档**：以标注、组件说明、导出页为准；推导方法不变，**盘点来源**改为画板/页面列表。**隐藏画板/隐藏图层**默认**不**生成需求，与 Axure HTML 中 \`display:none\` / \`visibility:hidden\` 策略一致，除非产品显式要求纳入。
- **仅 PDF**：以章节与表格为摘录单位；无文本图层时同「纯图」处理。

---

## 10. 与 \`/requirement-analysis\` 的衔接（通用）

从推导稿进入**写正式需求文档**时，**必须**使用 **\`/requirement-analysis\`** 技能包整体（逻辑名 **\`requirement-analysis\`**，**不**依赖某固定仓库路径）：

- 阅读该技能**主说明**（工作流程、输出格式、质量标准）。
- 一并使用其 **\`references/\`** 内被引用的标准与指南（如需求分析文档结构标准、5W1H 指南、评审清单等——**以技能包实际文件为准**）。
- 推导阶段产出仅作为**输入**；章节结构、术语与验收口径以 **\`/requirement-analysis\`** 为准。

## 11. 复杂模块的页面角色矩阵与深扫清单

对于类似“一个总表页 + 多个状态页 + 多个动作页 + 后管页”的复杂模块，建议先做**页面角色矩阵**，再做摘录，避免只抄总表页导致遗漏。

### 页面角色矩阵（推荐）

\`\`\`markdown
| 页面 | 角色 | 是否已读 | 是否有可见规则 | 需提取的信息 | 备注 |
|------|------|----------|----------------|--------------|------|
| 例：订单售后功能.html | 主规则页 | 是 | 是 | 总表、状态映射、汇总口径 | 不替代细节页 |
| 例：待商家发货状态.html | 状态页 | 是 | 是 | 发起入口、类型、原因、提交结果 | 补足操作细则 |
| 例：取消售后申请.html | 动作页 | 是 | 是 | 按钮条件、操作结果、状态变化 | 不能只在列表页顺带提及 |
| 例：订单售后业务流程图.html | 纯图页 | 是 | 否 | 仅记录为视觉参考 | 不直接抽条文 |
| 例：交易管理.html | 导航/占位页 | 是 | 否 | 记录无可见规则文本 | 防止误写正文规则 |
\`\`\`

### 深扫时必须覆盖的信息维度

| 页面类型 | 至少要提取什么 |
|----------|----------------|
| **主规则页** | 状态总表、汇总枚举、三端映射、汇总限制 |
| **状态页** | 当前状态入口、可发起类型、表单字段、原因枚举、上传项、是否审核、提交后结果 |
| **入口页** | Tab、状态顺序、跳转关系、进入哪个列表或详情 |
| **动作页** | 按钮显示条件、按钮点击后提示、状态翻转、次数限制、时效限制 |
| **列表/详情页** | 列字段、筛选项、操作列、详情展示块、协商历史/时间轴 |
| **后管页** | 菜单入口、状态页签、字段、处理按钮、同意/拒绝/超时结果 |
| **纯图页** | 只记录“需视觉评审”的结论类型，不直接造规则 |

### 复杂模块易漏点清单

- 只摘录总表页，漏掉**状态页里的表单字段、按钮、提交结果**。
- 只摘录列表字段，漏掉**动作页里的按钮条件和状态变化**。
- 把站点图中的页面都当成“有正文规则”，没有区分**占位页**与**规则页**。
- 没有横向核对**时效、类型、是否生成单据、是否翻转状态**，导致冲突未暴露。
- 忽略后管页，导致前台流程完整、后台处理规则缺失。

### 推荐输出骨架（针对复杂模块）

\`\`\`markdown
## 模块 X

### X.1 来源分层与可见性说明
- 主规则页：
- 支撑状态页：
- 动作页：
- 后管页：
- 纯图页：
- 无可见文本页：

### X.2 主规则页
### X.3 前台入口与状态页
### X.4 列表、详情与动作页
### X.5 后管处理页
### X.6 冲突 / 待确认
\`\`\`

该骨架尤其适用于订单、售后、履约、审批等存在**状态机 + 多端处理**的模块。
