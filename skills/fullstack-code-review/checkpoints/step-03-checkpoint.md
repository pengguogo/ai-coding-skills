# Checkpoint: Step 3 后端模块级审查

> **审查级别**：L1（轻量审查）— 只检查结构和内容维度。
> **审查原则**：你是审查者，不是作者。必须重新打开产出文件逐项核对，不能凭记忆判断。

## 审查时需打开的文件
- 产出文件：`{WORKSPACE}/review/03-backend-review-${instance-id}.md`
- 上游比对：`{WORKSPACE}/review/01-review-context.md`（检查策略字段）
- 上游比对：`{DESIGN}/backend-design.md`（对应设计章节）

## 结构检查
- [ ] 包含章节：审查范围（含模块名、task-split 编号、变更文件列表、审查策略）
- [ ] 包含章节：设计一致性复核（表格形式）
- [ ] 包含章节：审查发现（表格形式）
- [ ] 包含章节：模块摘要

## 内容检查
- [ ] 审查策略与 01-review-context.md 中该模块的检查策略一致
- [ ] `supplement` 策略时：发现表格中不包含 P0 级检查项编号（已被小节评审覆盖）
- [ ] `recheck` 策略时：发现表格中包含对小节评审遗留问题的复核
- [ ] `full` 策略时：发现表格中包含 P0 + P1 级检查项
- [ ] 设计一致性复核覆盖接口契约、领域模型、业务流程三个维度
- [ ] 每个 blocking/important 发现引用了具体检查项编号
- [ ] 每个发现标注了确信度（高/中/低）
- [ ] 低确信度发现标注了 `[需人工确认]`
- [ ] 模块摘要中的 blocking/important 数量与发现表格行数一致
- [ ] 发现编号使用 R{task_group_id}-{序号} 格式

## 待确认项提取
- 所有标注 `[需全局确认]` 的发现
- 所有标注 `[需人工确认]` 的发现
- 设计一致性复核中状态为 ❌ 不一致 或 ⚠️ 有偏差 的设计项
