# Commit 建议模板

> 本模板定义 commit 建议的输出格式。仅在审查全部通过后生成。
> 输出路径：`review/commit-suggestion.md`（存放在需求目录下）。
> commit 建议需人工确认后执行，AI 不自动提交。

---

## Commit 建议结构

```markdown
# Commit 建议

## 1. 基本信息

| 项目 | 内容 |
|------|------|
| 需求名称 | {需求名称} |
| 用户故事 ID | {US-001, US-002} |
| 审查结论 | ✅ 通过 |
| 审查报告 | [review-log.md](review-log.md) |
| 生成日期 | {YYYY-MM-DD} |

> **用户故事 ID 说明**：
> - 若 `requirement.md` 中包含用户故事 ID，直接使用。
> - 若缺失用户故事 ID，使用降级方案：`{需求目录名}` 或 `task-split.md` 主分类编号作为替代标识。
> - 降级标识格式：`REQ-{需求英文名}` 或 `TASK-{主分类编号}`。

## 2. 建议的 Commit 拆分

> 按功能模块拆分 commit，每个 commit 包含一个完整的功能单元。

### Commit 1：{功能描述}

**Commit Message**:
```
feat({模块名}): [{用户故事ID}] {功能描述}

- {变更说明 1}
- {变更说明 2}
```

**涉及文件**:

| 文件路径 | 变更类型 | 说明 |
|---------|---------|------|
| {src/main/java/.../ClaimService.java} | 新增/修改 | {说明} |
| {src/main/java/.../ClaimMapper.xml} | 新增/修改 | {说明} |

---

### Commit 2：{功能描述}

（同 Commit 1 结构）

---

### Commit N：数据库变更（如有）

**Commit Message**:
```
chore(db): [{用户故事ID}] {数据库变更描述}

- {DDL/DML 变更说明}
- 回滚脚本: {回滚脚本路径}
```

**涉及文件**:

| 文件路径 | 变更类型 | 说明 |
|---------|---------|------|
| {sql/V{版本号}__{描述}.sql} | 新增 | {DDL/DML 说明} |
| {sql/rollback/V{版本号}__rollback.sql} | 新增 | 回滚脚本 |

## 3. 完整文件清单

| 文件路径 | 变更类型 | 所属 Commit | 说明 |
|---------|---------|------------|------|
| {文件路径} | 新增/修改/删除 | Commit {N} | {说明} |

## 4. 人工确认事项

> 以下事项需人工确认后方可提交。

- [ ] **代码变更确认**：确认所有变更文件已包含在上述清单中，无遗漏。
- [ ] **用户故事 ID 确认**：确认 commit message 中的用户故事 ID 正确。{若使用降级标识，请确认是否需要补充正式的用户故事 ID。}
- [ ] **数据库变更确认**：确认 DDL/DML 脚本已在测试环境验证通过。{若无数据库变更，忽略此项。}
- [ ] **回滚脚本确认**：确认回滚脚本可正确执行。{若无数据库变更，忽略此项。}
- [ ] **配置变更确认**：确认新增配置项已在各环境配置中心/配置文件中就绪。{若无配置变更，忽略此项。}
- [ ] **审查遗留确认**：确认 review-log.md 中的遗留问题已处理或已知悉风险。{若无遗留问题，忽略此项。}

## 5. 未经 Review 的模块（如有）

> 若有模块被用户跳过审查，在此列出。

| 模块 | 跳过原因 | 风险说明 |
|------|---------|---------|
| {模块名} | {用户提供的原因} | {潜在风险} |

## 6. 提交后动作

- [ ] 触发 `project-archive` 归档
- [ ] 通知相关人员 review 已通过
- [ ] {其他项目约定的提交后动作}
```

---

## 降级方案说明

当 `requirement.md` 中缺少用户故事 ID 时，按以下优先级选择替代标识：

1. **需求目录名**：如需求目录为 `claim-approval_20250115`，则使用 `REQ-claim-approval`。
2. **task-split.md 主分类编号**：如后端主分类为 `1. 数据库设计`，则使用 `TASK-BE-1`。
3. **自定义标识**：由用户在人工确认时指定。

commit message 示例（降级）：
```
feat(claim): [REQ-claim-approval] 实现理赔审批功能

- 新增 ClaimApprovalService 审批逻辑
- 新增审批状态机流转
```
