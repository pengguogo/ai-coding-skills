# 交付追溯审计报告标准（`knowledge-recheck`）

本文件定义 `{BASE_DIR}/knowledge-recheck/knowledge-quality-report.md` 的**必备章节与判定口径**。产出为 UTF-8 Markdown，仅使用简体中文。

## 完整覆盖（强制）

- **禁止**抽样、抽检、随机抽查、代表性条目或「精简矩阵」
- 需求项追溯矩阵须 **100% 一行一项** 覆盖 Step 1 全部需求项
- 检查清单附录须包含 references 中 **全部** CK/AK/BK/PR（及 applicable CU）检查项 ID
- code-scope / hybrid 时，代码范围反查表须 **100%** 覆盖 Step 1 代码范围索引
- 未归档项、知识库未更新项须 **逐条** 列出，禁止「等多项」「部分功能」等合并描述
- Step 2 覆盖统计非 100% 时 **不得** 进入 Step 3 落盘

## 总体判定规则

| 判定 | 条件 |
|------|------|
| ✅ **通过** | 流水线阶段无 P0 缺口；archive 三件套齐全（若代码/设计已存在）；知识库对本次需求项覆盖 complete 或 partial 且 partial 均有说明 |
| ⚠️ **部分通过** | 存在 P1 缺口（知识库 outdated/partial、评审缺失等）或存在 `[需人工确认]` 项，但不阻塞归档决策 |
| ❌ **不通过** | 存在 P0 缺口：已实现功能未归档（archive 缺失）、知识库 critical 缺失（如新增接口未写入接口清单——目录或存量单文件均可）、或需求文档与代码严重不一致 |

P0 / P1 划分见各章节「严重程度」列。

## 状态字段取值

- **流水线/文档状态**：`complete` | `partial` | `missing` | `not-applicable`
- **知识库状态**：`complete` | `partial` | `missing` | `outdated` | `not-applicable`
- **综合状态**：`✅` | `⚠️` | `❌`

## 禁止事项

- 禁止抽样、抽检、精简矩阵或省略检查项 ID
- 禁止在报告中声称已执行归档或知识库更新（本技能仅质检）
- 禁止无证据路径的判定
- 禁止将 custom/ 列为「待融合更新」目标（custom 只读，见 scheduler-protocol §1.5.1）
