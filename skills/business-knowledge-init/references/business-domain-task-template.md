# 业务架构梳理任务规划（Task Template）

## 1 文档目的与定位

当系统涉及的业务场景（S-*）或业务流程极多时，AI 需要生成此 \`task.md\` 来管理工作进度。

**生成原则**：
- 在生成任何主业务文档之前，优先输出此规划文档。
- 作为 AI 的 Todo 列表，确保所有的业务梳理环节不被遗漏。
- 对于多场景项目，任务必须体现出"先全景后细节"、"按场景分批"的策略。

---

## 2 task.md 模板

**格式**：
\`\`\`markdown
# 业务架构梳理任务规划

## 1. 基础信息

| 字段 | 内容 |
|------|------|
| 目标文档 | \`business-overview-and-planning.md\` 等四份业务文档 |
| 涉及业务域/场景范围 | [列出识别到的业务群或核心场景清单] |
| 基线与输入 | [列出读取的 knowledge/code/ 路径及用户补充的业务材料] |
| 应用基线状态 | [knowledge/application/ 是否已存在，若存在则 S-* 需复用] |

## 2. 任务列表

| ID | 任务项 | 状态 | 前置任务 | 产出目标 |
|----|--------|------|----------|----------|
| T1 | 梳理系统业务全景，提取业务群(BG)、业务(B)和场景(S)清单 | [ ] | — | 写入全景册 ## 1~3 |
| T2 | 绘制主业务价值流、业务群关系图、业务全景 mindmap，梳理双链并存（若有） | [ ] | T1 | 写入全景册 ## 4~7 |
| T3 | 梳理核心参与者，绘制用例图（按业务域分组），绘制端到端主流程图 | [ ] | T1 | 写入流程册 ## 1~3 |
| T4 | 逐个场景推导业务流程（阶段→活动→任务→步骤→DE），含可变点和流程图 | [ ] | T1, T3 | 写入流程册 ## 4 |
| T5 | 逆向推导领域模型：子域(SD)关系图+清单、领域对象(DO)按子域分组、领域事件(DE)清单 | [ ] | T4 | 写入领域册 ## 1~3 |
| T6 | 将业务流程与领域事件串联（串联表+串联图），绘制领域模型 ER 关系图 | [ ] | T4, T5 | 写入领域册 ## 4~5 |
| T7 | 提取业务用例（按参与者分组），绘制领域事件全景串联图和参与者-用例关系图 | [ ] | T4, T5 | 写入流程册 ## 5~7 |
| T8 | 梳理业务能力清单（按BG分组）、场景-组件映射（S→AC）、能力地图、DE→技术映射、术语表、附录A | [ ] | T1, T5 | 写入能力附录册 ## 0~6 |
| T9 | 全局校验 ID 一致性及"流程-事件"闭环 | [ ] | T1-T8 | 终态检查 |

## 3. 依赖关系说明

- T1 是所有后续任务的前置，必须先完成业务全景梳理。
- T2 聚焦全景册的图表（价值流+BG关系图+mindmap+双链），依赖 T1。
- T3 聚焦流程册的参与者、用例图和主流程图，依赖 T1。
- T4 聚焦流程册的各场景独立流程（含流程表+可变点+流程图），依赖 T1 和 T3。
- T5 聚焦领域册的子域/DO/DE，依赖 T4 的流程输出。
- T6 聚焦领域册的串联表+串联图+ER关系图，需要 T4 和 T5 同时完成。
- T7 聚焦流程册的用例概览+DE串联图+参与者-用例图，依赖 T4 和 T5。
- T8 聚焦能力附录册全部章节（能力地图+BC清单+S→AC映射+DE→技术映射+术语表+附录A），依赖 T1 和 T5。
- T9 为终态校验，必须在所有产出任务完成后执行。
\`\`\`

---

## 3 内容标准

- 基础信息：必须明确写明分析的输入来源（代码反推还是参考了其他补充材料）和应用基线状态。
- 任务列表：按"全景 → 流程 → 模型 → 串联 → 能力"的逻辑顺序编排，前置任务列必须填写。
- 依赖关系说明：用文字简要说明任务间的依赖逻辑，便于用户评审时理解执行顺序。

---

## 4 生成约束

- 只有在判定为大篇幅/复杂场景时才生成此文件。
- **生成后直接按任务顺序执行，无需等待用户确认。**
- **在所有任务执行完毕且经用户最终确认后，必须删除此临时任务清单文件。**
- 状态栏必须使用标准 Markdown Checkbox 语法 \`[ ]\` 或 \`[x]\`。
