# 外部依赖

本文档是项目初始化标准中涉及的外部依赖相关规范。列出项目依赖的外部系统和服务，包含**业务系统**、**第三方服务**。

---

## 1 说明

外部依赖包括：依赖的其他业务系统与服务、第三方服务与 API。**存量项目**可根据代码扫描（如 HTTP/RPC 客户端调用、配置中的服务地址等）进行识别与填充。

**强制执行扫描任务模板**：生成 \`backend-external-dependency.md\` 时，**必须**按 [unified-scan-task-template.md](../../unified-scan-task-template.md) 任务模板中的外部依赖扫描注册表执行扫描流程。**不得**跳过扫描步骤直接生成外部依赖清单。

**接口信息必填与一次生成原则**：
- 凡通过 HTTP/OpenAPI/RPC 等调用的**业务系统**或**第三方服务**，必须为**每个实际调用的接口**填写完整的接口信息，不得省略或写"见后续补充"。
- **必填项**（每条接口均须输出，从代码/配置中提取）：**接口路径**（含 HTTP 方法与路径或 URL 占位）、**功能描述**。**错误码**在代码或配置中存在时一并输出（否则不强制）。
- 上述信息优先从调用代码（如 \`RestTemplate\`/\`HttpClient\`/Feign 的 URL、请求体、响应处理）和配置文件（如 \`application*.yml\`、\`@Value\` 注入的 URL）中扫描得出；仅当某字段在代码与配置中均无法推断时，才使用 \`[需人工确认]\`，并尽量减少此类项。
- 生成文档时应**一次输出完整**，避免依赖用户多次补充指令再补全接口信息。

## 2 外部依赖全景

> 在详细列表之前，先用一张图和一张表给出全貌。数据来源为 \`application*.properties\`/\`application*.yml\`、代码中的 HTTP/RPC 客户端调用、MQ 配置等。

### 2.1 外部依赖关系图

使用 Mermaid graph LR 绘制，中心节点为当前项目，按类型分组（业务系统、第三方服务、基础设施）展示所有外部依赖。箭头标注调用方式，虚线表示本地依赖（如本地缓存），实线表示远程依赖。

**输出格式**：
\`\`\`markdown
#### 外部依赖关系图

\`\`\`mermaid
graph LR
    APP[当前项目名称]

    subgraph 业务系统
        SYS1[业务系统A]
        SYS2[业务系统B]
    end

    subgraph 第三方服务
        THIRD1[第三方服务A]
    end

    subgraph 基础设施
        MQ[消息队列<br/>RocketMQ/Kafka等]
        CACHE[缓存<br/>Redis等]
        CONFIG[配置中心<br/>Apollo/Nacos等]
    end

    APP -->|HTTP| SYS1
    APP -->|Feign| SYS2
    APP -->|HTTP| THIRD1
    APP -->|Producer/Consumer| MQ
    APP -->|读写| CACHE
    APP -->|配置拉取| CONFIG
\`\`\`
\`\`\`

**生成规则**：
- 中心节点使用当前扫描项目的实际名称
- 按文档已有分类分组：业务系统、第三方服务、基础设施
- 箭头标注调用方式（HTTP/Feign/MQ/读写/配置拉取等）
- 虚线（\`-.->|方式|\`）表示本地依赖（如本地缓存），实线表示远程依赖
- 节点名称使用简短可识别的名称，必要时用 \`<br/>\` 换行补充说明
- 单图节点不超过 20 个；超过时可省略次要基础设施依赖
- **禁止照抄示例中的占位名称**，必须替换为实际扫描到的依赖
