# Bug 分级 / 类型路由 / 越界阈值标准

本文件为 `bug-fix` 技能的判级、类型路由与越界判定权威来源。Step 1 判级、Step 2 定向、Step 3 越界检查均引用本文件。

---

## 1. 分级模型（L1/L2/L3，只控制校验深度）

| 级别 | 判定特征 | 定位深度 | 校验深度 |
|---|---|---|---|
| **L1 轻量** | 改文案/常量/配置、纯样式、明显空指针、单文件单点、无调用链扩散 | 单点定位（纯样式跳过调用链） | 静态因果自证 + 最小编译（纯逻辑加单测） |
| **L2 标准** | 单模块逻辑、有限调用链（≤1 跨层）、无数据/联动风险 | ≤1 跨层调用链 | L1 全部 + 影响面比对 |
| **L3 严格** | 跨模块/前后端联动/DDL/资金核心/并发/安全 | 完整调用链 + 上下游 caller | L2 全部 + code-reviewer 审查 + 反向引用 |

> **复现/验证策略正交于级别**：单测 vs 人工回归点由「根因是否纯逻辑」决定，不由 L1/L2/L3 决定。级别只决定「定位深度 + 是否加 code-reviewer/影响面比对」。

## 2. 判级机械证据强制项（防作弊）

Step 1 判级**必须**在产出列出可机械核查的证据：

| 证据项 | 取值 |
|--------|------|
| 涉及仓库数 | 1 个 / 多个 |
| 预估调用链跨层数 | 0 / ≤1 / >1 |
| 含 SQL DDL | 是 / 否 |
| 触及资金 / 并发 / 鉴权关键路径 | 是 / 否 |
| 前后端联动 | 是 / 否 |

**硬约束**：
- 缺任一证据项 → **强制 fallback 到 L2**
- 含 DDL / 触及资金·并发·鉴权 / 前后端联动 任一为「是」→ **至少 L3**
- **用户可升档，AI 不得自我降级**
- 判级须向用户明示并接受纠偏

## 3. 类型路由（缩小定向范围，与分级正交）

| 类型 | 定向方向 |
|---|---|
| 后端逻辑 | 按布局判定读 backend-interface 入口 → 命中域文件；追 Controller→Service→DAO→Mapper |
| 前端逻辑 | `frontend-project.md`；追 View→Component→API |
| 前后端联动 | 两端各命中 + 接口契约一致性（契约以**真实代码为第一来源**） |
| 数据库/DDL | 按布局判定读 backend-database 入口 → 命中表文件 |
| 前端纯样式 | 并入前端逻辑路径，但**只定位样式/组件文件，跳过调用链追溯** |

**归并规则**（无独立档的类型）：
- 性能类 → 按主导症状归并（DB 慢 → 数据库；接口慢 → 后端逻辑；渲染卡 → 前端逻辑）
- 并发类 → 后端逻辑，且**强制 L3**
- 安全类 → 对应端逻辑，且**强制 L3**

## 4. 方案越界阈值（Step 3 越界检查）

命中任一 → STATUS_REPORT `BLOCKED` → 升级 `fullstack-design` + `task-split`，终止 bug-fix：

- 需新增/变更对外接口签名或 DTO 字段
- 需 DDL 结构变更（建表 / 改字段类型 / 加索引以外的结构变更）
- 需引入新模块 / **新依赖** / 新状态机（**调整已有依赖版本**不算越界，但强制 L3 + 回归审查）
- 修复涉及文件数 **> 8**（阈值可调）

## 5. 不变底线（任何级别均不省）

1. 根因须真实读码、不臆测（报错行 ≠ 根因行）
2. 改前必经一道确认门禁（Phase 2 末）
3. 改完必跑最小编译
4. 分级须向用户明示并接受纠偏
5. 任何级别均执行单一复现/验证策略：静态因果自证强制 + 按根因纯逻辑性互斥触发单测复现 / 人工回归点清单
