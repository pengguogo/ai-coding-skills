# bug-fix-log 记录模板

Step 7 按本模板**追加**到 `{BASE_DIR}/bug/bug-fix-log.md`（不覆盖既有行，不含 STATUS_REPORT）。

## 表格结构

```markdown
| Bug 编号 | 方案文件 | 关联需求 | 现象 | 影响模块 | 类型 | 级别 | 根因摘要 | 修复文件清单 | 验证方式 | 编译结果 | 回归审查 | knowledge 偏离 | 状态 |
|---------|---------|---------|------|---------|------|------|---------|------------|---------|---------|---------|---------------|------|
| BUG-20260624-01 | [方案](BUG-20260624-01-审批链推送OA失败-fix-plan.md) | oa-approval-integration_20260616 | … | … | 后端逻辑 | L2 | … | repoA: src/... | 单测复现转绿(TxxTest#m) | PASS | N/A(非L3) | 否 | 已修复 |
```

## 字段规则

| 字段 | 规则 |
|------|------|
| Bug 编号 | `BUG-<yyyymmdd>-<NN>`，`<NN>` 当日 log 内自增两位序号；一次运行修一个 bug，追加写入避免并发冲突 |
| 方案文件 | 指向同目录持久方案 `<id>-<slug>-fix-plan.md` 的相对链接 |
| 关联需求 | 即 `{BASE_DIR}` 对应的需求目录名 |
| 类型 | 后端逻辑 / 前端逻辑 / 前后端联动 / 数据库 / 前端纯样式 |
| 级别 | L1 / L2 / L3 |
| 修复文件清单 | 按仓库分组列实际改动文件（相对仓库根） |
| 验证方式 | `单测复现转绿(<测试类#用例>)` / `静态自证+人工回归点(<N>条)` / `[无测试基建]` |
| 编译结果 | PASS / SKIP（与 Step 5 build-verify 一致） |
| 回归审查 | L3：code-reviewer 判定 PASS / PASS_WITH_NOTES / FAIL（取自 `code-review.md`）；非 L3：`N/A(非L3)` |
| knowledge 偏离 | `否` 或 `是 → 建议 project-archive 更新 <文档>`（**不回灌** knowledge，仅标记供人工追踪） |
| 状态 | 已修复 / 部分修复（含待人工确认项） |

## 静态因果自证（每条 bug 附，置于表格下方）

```markdown
### BUG-<yyyymmdd>-<NN> 静态因果自证
- 根因：<文件:行号> —— <为何出错>
- 本次修改：<文件:行号> —— <改了什么>
- 现象消失：<文件:行号> —— <原触发路径上为何不再复现>
```

## 文件头（首次创建时）

```markdown
# Bug 修复记录（bug-fix-log）

> 本文件由 `bug-fix` 技能追加维护。每行一个 bug，编号 BUG-<yyyymmdd>-<NN>。
> knowledge 偏离仅标记，不回灌知识库；偏离修复由 project-archive 处理。
```
