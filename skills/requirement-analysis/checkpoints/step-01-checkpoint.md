# Checkpoint: Step 1 输入接收 + 5W1H 分析 + 需求项建模

> **审查级别**：L1（轻量审查）— 只检查结构和内容维度，全局一致性延迟到 Step 2 的 L2 审查。
> **审查原则**：你是审查者，不是作者。必须重新打开产出文件逐项核对，不能凭记忆判断。

## 审查时需打开的文件
- 输入摘要：`{WORKSPACE}/requirement/01-intake.md`
- 事实源表：`{WORKSPACE}/requirement/01-fact-source.md`
- 建模产出：`{WORKSPACE}/requirement/01-modeling.md`

## 输入摘要检查（01-intake.md）
- [ ] 包含业务目标
- [ ] 包含干系人/用户角色（表格，至少 1 行）
- [ ] 包含功能列表（表格，至少 1 行，含复杂度和依赖列）
- [ ] 包含已知约束、范围外/明确不做
- [ ] 包含 5W1H 分析（Why/What/Who/When/Where/How 六个章节）
- [ ] What 包含验收口径（Given-When-Then 表格，至少 1 行）
- [ ] Who 包含角色清单表格
- [ ] How 包含关键业务规则表格
- [ ] 包含 §9 事实源摘要（条目总数 + F1~F5 分布 + F5 待降级条目数）

## 事实源表检查（01-fact-source.md，Phase A3 产出）
- [ ] 文件存在且非空（缺失则 Step 2 门禁无法执行）
- [ ] §1 登记表列完整：事实源 ID / 事实内容 / 级别 / 来源文件 / 定位锚点 / 原文摘录 / 关联需求项 / 校验状态
- [ ] 事实源 ID 从 FS-001 起连续、无重复
- [ ] 级别取值均为 F1~F5 之一
- [ ] 定位锚点精度达标（含章节号/表格行/页码/图片文件名；无「材料里有」「知识库中提到」这类无法定位的写法）
- [ ] F1 条目均填了原文摘录
- [ ] 功能列表中每个需求项至少有 1 条关联事实源
- [ ] 含 §2 级别分布统计、§3 数字型事实清单、§4 F5 待降级条目
- [ ] §3 数字型事实清单中所有条目级别均为 F1/F2（无 F3/F4/F5）
- [ ] 校验状态列统一为「待校验」

## 溯源挂载检查（01-modeling.md，Part 2.5）

## 三维度逻辑强制检查（涉及前端交互的需求项）
- [ ] 页面操作维度：入口位置、操作顺序、禁用/置灰条件、校验提示文案

- [ ] 数据交互维度：接口或消息、请求参数、响应字段、幂等与重试

## 平台信息检查（涉及前端界面或终端渠道的需求项）
- [ ] 每个前端需求项的建模产出包含 §3.1.1 平台适用与差异

- [ ] 材料不足时 `Applicable_Platforms` 写"待确认"且 `Pending` 记录了原因、影响和待确认问题（未伪造默认值）
- [ ] 多端需求有非空 `Shared_REQ_Trace`
- [ ] 多端需求有 `Common_Acceptance_Criteria` 和 `Platform_Difference` 表格（或明确"无额外差异"声明）
- [ ] HMOS 的页面操作、数据展示、数据交互和验收与其他端同等完整
- [ ] `Web_H5_Merge` 声明（若有）与 `Applicable_Platforms` 一致
- [ ] Where 分析产出中的平台归一化结果与 §3.1.1 一致
