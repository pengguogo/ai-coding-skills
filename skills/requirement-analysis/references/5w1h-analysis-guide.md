# 5W1H 需求分析法指南

## 什么是5W1H分析法

5W1H分析法是一种系统化的需求分析方法，通过回答六个核心问题来全面理解和拆解需求，识别隐藏的业务场景。

## 5W1H 六要素

### 1. Why（为什么）
**目的**：理解需求的背景、动机和业务价值

**关键问题**：
- 为什么需要这个功能？
- 解决什么业务问题？
- 带来什么价值或收益？
- 不做会有什么影响？
- 优先级为什么是这个？

**分析要点**：
- 识别业务痛点
- 理解用户动机
- 明确业务目标
- 评估需求合理性

**示例**：
\`\`\`
Why: 为什么需要用户登录功能？
- 为了保护用户数据安全
- 提供个性化服务
- 追踪用户行为
- 满足合规要求
\`\`\`

### 2. What（是什么）
**目的**：明确需求的具体内容和范围

**关键问题**：
- 具体要实现什么功能？
- 功能的边界在哪里？
- 包含哪些子功能？
- 不包含什么（排除项）？
- 输入和输出是什么？

**分析要点**：
- 明确功能范围
- 定义输入输出
- 识别包含和排除项
- 确定验收标准

**示例**：
\`\`\`
What: 用户登录功能包含什么？
包含：
- 用户名密码登录
- 手机号验证码登录
- 记住登录状态
- 密码找回

不包含：
- 第三方登录（微信、支付宝等）
- 生物识别登录
- 多因素认证
\`\`\`

### 3. Who（谁）
**目的**：识别需求的利益相关者和用户角色

**关键问题**：
- 谁会使用这个功能？
- 谁会受到影响？
- 谁来决策和审批？
- 谁来开发和测试？
- 有哪些不同的用户角色？

**分析要点**：
- 识别用户角色
- 分析用户特征
- 理解用户需求差异
- 考虑权限和访问控制

**示例**：
\`\`\`
Who: 谁会使用登录功能？
- 普通用户：需要登录访问个人账户
- 管理员：需要登录管理系统
- 客服人员：需要登录客服系统
- 系统审计员：需要查看登录日志

用户特征差异：
- 普通用户：关注易用性
- 管理员：关注安全性
- 客服人员：关注效率
\`\`\`

### 4. When（何时）
**目的**：明确需求的时间维度和触发条件

**关键问题**：
- 什么时候需要这个功能？
- 什么时候触发这个功能？
- 有什么时间限制或截止日期？
- 是一次性需求还是持续需求？
- 什么时候上线？

**分析要点**：
- 识别触发时机
- 理解时间约束
- 明确上线计划
- 考虑时效性要求

**示例**：
\`\`\`
When: 登录功能的时机
触发时机：
- 用户访问需要认证的页面时
- 会话过期时
- 用户主动点击登录时

时间约束：
- 需要在Q2上线
- 登录响应时间<2秒
- 密码错误锁定5分钟
\`\`\`

### 5. Where（何地）
**目的**：明确需求的应用场景和环境

**关键问题**：
- 在什么场景下使用？
- 在什么设备上使用？
- 在什么网络环境下使用？
- 有什么环境限制？
- 需要与其他哪些系统集成？

**分析要点**：
- 识别使用场景
- 考虑设备和环境
- 分析集成需求
- 理解环境约束

**示例**：
\`\`\`
Where: 登录功能的使用场景
使用场景：
- PC端浏览器登录
- 移动端H5登录
- App内登录
- 公共场所设备登录

环境要求：
- 支持主流浏览器
- 适配不同屏幕尺寸
- 支持弱网环境
- 需要与用户系统集成
\`\`\`

### 6. How（如何）
**目的**：明确需求的实现方式和操作流程

**关键问题**：
- 如何实现这个功能？
- 用户如何操作？
- 系统如何处理？
- 有什么技术约束？
- 如何保证质量？

**分析要点**：
- 设计用户流程
- 确定技术方案
- 定义处理逻辑
- 制定质量标准

**示例**：
\`\`\`
How: 登录功能的实现方式
用户操作流程：
1. 用户打开登录页面
2. 输入用户名和密码
3. 点击登录按钮
4. 系统验证凭证
5. 登录成功跳转首页

系统处理逻辑：
- 前端表单验证
- 服务端身份验证
- 会话管理
- 日志记录

技术约束：
- 使用JWT令牌
- 密码加密存储
- 支持HTTPS
\`\`\`

## 识别隐藏业务场景

### 常见隐藏场景

1. **边界场景**：
   - 极值情况（最大值、最小值）
   - 空值处理
   - 异常数据

2. **异常场景**：
   - 网络异常
   - 系统故障
   - 并发冲突

3. **特殊场景**：
   - 特殊用户角色
   - 特殊时间点
   - 特殊业务状态

4. **集成场景**：
   - 跨系统操作
   - 数据同步
   - 第三方服务调用

### 隐藏场景识别检查清单

- [ ] 是否考虑了所有用户角色？
- [ ] 是否考虑了异常和错误情况？
- [ ] 是否考虑了边界和极值情况？
- [ ] 是否考虑了并发和性能问题？
- [ ] 是否考虑了安全和合规要求？
- [ ] 是否考虑了与其他系统的集成？
- [ ] 是否考虑了数据迁移和兼容性？
- [ ] 是否考虑了运维和监控需求？

## 实践建议

1. **系统性分析**：按照5W1H的顺序逐一分析，确保不遗漏
2. **多角度思考**：从用户、开发、测试、运维等不同角度思考
3. **持续追问**：对每个答案持续追问"为什么"，深入挖掘
4. **交叉验证**：通过不同维度的问题交叉验证需求的一致性
5. **文档化**：将分析结果记录下来，便于评审和追溯
6. **迭代完善**：在评审过程中根据反馈不断完善分析
