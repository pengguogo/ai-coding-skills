# Step 1: SQL 解析与目标识别

## 元信息

- execution-mode: inline

## 参数

- input: 用户提供的订正 SQL 语句
- output: 结构化 SQL 解析清单（内存，传递给后续步骤）

## 执行指令

1. 逐条解析用户提供的 SQL 语句，提取：
   - 目标表名
   - 修改字段列表（SET 子句中的字段）
   - WHERE 条件（定位影响范围，提取 key 字段和值）
   - SET 值（判断业务语义，如常量/表达式/函数调用）

2. 对每条 SQL 生成业务语义摘要（一句话描述修改意图）

3. 识别跨 SQL 的关联性：
   - 多条 SQL 是否涉及同一 internal_key 或同一客户
   - 是否存在执行顺序依赖

4. 将解析结果整理为概览表：

   | # | 目标表 | 涉及字段 | 目标 Key | SQL 概要 |
   |---|--------|---------|----------|----------|

5. 确定场景名（用于报告命名）：从 SQL 涉及的表和业务语义中提取

## 产出

- SQL 订正内容概览表
- 场景名标识
- 每条 SQL 的结构化解析对象（表名、字段列表、WHERE、SET、语义摘要）
