# Step 3: 后置功能影响分析

## 元信息

- execution-mode: inline

## 参数

- input: Step 1 的 SQL 解析结果 + Step 2 的代码引用清单
- output: 后置功能影响明细表

## 执行指令

基于 Step 2 的代码引用，逐条 SQL 分析后置功能影响：

### 分析维度

1. **直接触发的功能**
   - 哪些 EOD Job 或在线交易会因字段值变化而被触发/跳过
   - 重点：WHERE 条件中引用目标字段的 EOD 查询

2. **计算链影响**
   - 字段值参与哪些下游计算（如金额分配、日期推算、利率计算）
   - 重点：SET 子句或 Java 代码中将目标字段作为输入参数的逻辑

3. **覆盖风险**
   - 哪些 EOD Job 会重新计算并覆盖手动订正值
   - 重点：UPDATE 语句中 SET 目标字段 = 计算结果的 Mapper SQL

### 对每条 SQL 输出

**字段含义表：**

| 字段名 | 业务含义 |
|--------|---------|

**影响分析表（整合后置功能 + 事实源 + 触发条件 + 影响结论）：**

| 后置功能 | 触发条件 | 影响结论 |
|---------|---------|---------|

每行记录包含：
- **后置功能列**：功能名称 + 类型（EOD/在线/会计），紧跟其下展示事实源（完整文件路径 + 行号）
- **触发条件列**：SQL 条件原文或代码判断逻辑，附补充说明
- **影响结论列**：本次修改对该功能的具体影响判定，使用标签：
  - ✅ 安全（功能不受影响或影响符合预期）
  - ⚠️ 需关注（行为有变化，需人工确认）
  - ❌ 危险（会导致错误或异常）

### 关键说明块

当存在以下情况时，使用独立的「关键说明」段落：
- 复杂的间接触发逻辑（如 next_cycle_date 先转为 last_cycle_date 再触发）
- EOD 覆盖风险的检查结论
- 系统正常行为与本次 SQL 修改的差异点

## 产出

- 逐条 SQL 的影响分析明细（字段含义 + 整合影响分析表 + 关键说明）
- 影响分析表每行自带事实源引用，无需独立事实源列表
