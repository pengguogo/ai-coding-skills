# Step 4: 风险评估与分级

## 元信息

- execution-mode: inline

## 参数

- input: Step 3 的后置功能影响明细
- output: 风险点汇总表

## 执行指令

对 Step 3 中所有识别到的后置功能影响进行风险分级。

### 风险等级标准

| 等级 | 判定标准 | 典型场景 |
|------|----------|---------|
| P0-高 | 会导致错误出单/错误扣款/金额计算错误/数据被覆盖 | EOD 错误触发出单、金额计算偏差、手动订正被覆盖 |
| P1-中 | 会影响后续期次计算/会计凭证/日期偏移 | 后续期日期偏移、GL 凭证异常、频率参数不一致 |
| P2-低 | 影响审计字段/条件宽泛可能多改/关联性待确认 | WHERE 匹配多条记录、跨 key 关联未确认 |

### 风险点输出格式

每个风险点包含：

| 字段 | 说明 |
|------|------|
| 风险等级 | P0-高 / P1-中 / P2-低 |
| 风险点 | 简短标题（如"SQL-1 本金出单时机"） |
| 说明 | 具体影响描述，含代码引用 |
| 建议 | 应对措施或确认事项 |

### 分级规则

1. 凡涉及金额字段被 EOD 重算覆盖 → 至少 P0
2. 凡 next_deal_date / next_cycle_date 被修改且会触发 EOD 出单 → P0
3. 凡 deal_day / int_day 等频率参数被修改影响后续期次 → P1
4. 凡会计模块（GL）有依赖 → 至少 P1
5. 凡 WHERE 条件可能匹配多条记录 → P2
6. 凡多 key 关联未确认 → P2

### 排序规则

风险点按等级排序：P0 在前，P2 在后。同等级内按 SQL 编号排序。

## 产出

- 风险点汇总表（按等级排序）
