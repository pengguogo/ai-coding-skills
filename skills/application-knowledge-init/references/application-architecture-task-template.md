# 应用架构生成任务规划（Task Template）

## 1 文档目的与定位

当系统包含较多应用（如 APP >= 8）或需要分批梳理架构知识（如包含 8+ 子系统的大型项目）时，AI 需要生成此 \`task.md\` 来管理工作进度。

**生成原则**：
- 在生成任何主架构文档之前，优先输出此规划文档。
- 作为 AI 的 Todo 列表，确保所有关键环节不被遗漏。
- 对于超大项目，任务必须体现出"分批次读取"、"先全局后局部"的策略。

---

## 2 task.md 模板

**格式**：
\`\`\`markdown
# 应用架构梳理任务规划

## 1. 基础信息

| 字段 | 内容 |
|------|------|
| 目标文档 | \`application-system-architecture.md\` 等三份文档 |
| 涉及子系统/域 | [列出识别到的所有子系统清单] |
| 基线范围 | [列出将读取的 knowledge/code/ 下的具体路径] |
| 业务基线状态 | [knowledge/business/ 是否已存在，若存在则 S-* 需对齐] |

## 2. 任务列表

| ID | 任务项 | 状态 | 前置任务 | 产出目标 |
|----|--------|------|----------|----------|
| T1 | 批量读取各子系统扫描基线，提取应用组(AG)与核心应用(APP)列表 | [ ] | — | AG/APP 清单 |
| T2 | 绘制全局系统分层与集成拓扑图 | [ ] | T1 | 写入系统册 ## 2 |
| T3 | 梳理端到端调用链（从前端入口开始），绘制各核心链路时序图 | [ ] | T1 | 写入系统册 ## 3 |
| T4 | 梳理跨子系统的全局集成点（外部/内部/前后端），输出集成表 | [ ] | T1 | 写入系统册 ## 4 |
| T5 | 梳理部署架构概要（后端部署/前端部署） | [ ] | T4 | 写入系统册 ## 5 |
| T6 | 绘制应用组全景图与渠道映射图，填充 AG 台账与 APP 台账、依赖矩阵、渠道映射、前端应用与后端能力总览 | [ ] | T1 | 写入主数据册 ## 0~5 |
| T7 | 绘制组件全景图（含组件数 > 10 的 APP 按业务域在子表下方生成局部视图），分批梳理各 APP 核心组件(AC)，填充组件表 | [ ] | T6 | 写入组件册 ## 0~N |
| T8 | 梳理渠道定制组件差异与前端应用组件概要 | [ ] | T7 | 写入组件册 |
| T9 | 全局校验 ID 命名空间、图表节点与表格一致性 | [ ] | T2-T8 | 终态检查 |

## 3. 依赖关系说明

- T1 是所有后续任务的前置，必须先完成基线读取。
- T2~T5 聚焦系统册（架构图→调用链→集成点→部署），按顺序执行。
- T6 聚焦主数据册（全景图+AG/APP台账+依赖矩阵+渠道映射+前端应用与后端能力总览），依赖 T1。
- T7 聚焦组件册的组件全景图和各 APP 组件清单，依赖 T6（需要 APP 编号）；对于超大项目可按子系统拆分子任务（如 T7.1、T7.2）。
- T8 聚焦组件册的渠道差异和前端概要，依赖 T7。
- T9 为终态校验，必须在所有产出任务完成后执行。
\`\`\`

---

## 3 内容标准

- 基础信息：必须明确写明分析的边界（使用了哪些子系统的基线）和业务基线状态。
- 任务列表：按依赖顺序编排，前置任务列必须填写。对于超大项目，T7 可拆分为多个子任务。
- 依赖关系说明：用文字简要说明任务间的依赖逻辑，便于用户评审时理解执行顺序。

---

## 4 生成约束

- 只有在判定为大篇幅/复杂场景/多子系统时才生成此文件。
- **生成后直接按任务顺序执行，无需等待用户确认。**
- **在所有架构知识文档生成完毕且经用户最终确认后，必须删除此临时任务清单文件。**
- 状态栏必须使用标准 Markdown Checkbox 语法 \`[ ]\` 或 \`[x]\`。
