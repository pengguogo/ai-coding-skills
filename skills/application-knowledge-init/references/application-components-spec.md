# 应用组件清单规范

本文档定义 \`application-components.md\`（应用组件与能力）的完整输出模板、内容标准与生成约束。

---

## 1 文档定位

应用组件册侧重应用内部组件（AC）、应用服务（AS）、扩展点（EP）及数据对象（DO）等能力清单，是三份应用架构文档中的"能力视图"。

---

## 3 内容标准与填表指南

- **应用组件 (AC)**：对于大型项目，优先梳理对外提供能力的核心组件，忽略内部琐碎实现（如 Utils, Constants 等）。组件通常对应代码中的顶层 package 或 Maven 子模块。
- **组件画布**：用一张表展示单个组件的全貌。组件总数 ≤ 10 时全部生成；> 10 时仅为核心流转类组件生成，支撑/配置类组件可省略。
- **应用服务 (AS)**：对外暴露的核心业务能力，由一个或多个应用组件实现。表中"对应业务活动"列用于追溯该服务支撑的业务流程。
- **扩展点 (EP)**：组件对外提供的可扩展接口，用于不同业务身份的差异化实现（如策略模式、SPI）。无扩展点的项目可省略此表。
- **数据对象（应用架构视角）**：应用侧管理的核心数据对象。"管理组件"指负责该对象 CRUD 的组件；"来源组件"指创建或产生该对象的上游组件；"来源领域对象"用于追溯到 \`knowledge/business/\` 下领域建模文档中的 DO-* 编号（若存在）。
- **不变量**：数据对象必须始终满足的业务约束（如状态机单向流转、金额非负等）。"保障组件"指负责校验和维护该不变量的组件。无不变量的项目可省略 4.2 表。
- **应用组件间依赖**：梳理组件之间的调用、数据、事件依赖关系。重点关注跨应用的组件依赖，同一应用内部的组件依赖可省略。依赖类型分为：调用（Feign/HTTP）、数据（共享库/缓存）、事件（MQ）。
- **全局构建块映射**：表达从业务流程到技术实现的完整追溯链。每行从左到右读：某个业务流程**使用**了哪个应用服务（AS），该服务由哪个应用组件（AC）**实现**，组件**操作**了哪个数据对象（DO）。
- **易混概念/差异表**：用于解决大型项目中极易出现的"同名概念"冲突（如每个子系统都有一个 User 模块，但职责完全不同）。

## 4 生成约束

- \`所属应用/子系统\` 必须能在 \`applications-and-domains.md\` 中找到对应的标识。
- \`AC-*\` 编号应包含子系统/应用的前缀信息以示归属。
- 如果某子系统的代码未详细扫描，其组件和扩展能力清单可标记为 \`[待补充]\`。
- 无扩展点的项目，3.2 扩展点表可省略或写「无」。
