# Checkpoint: Step 2 事实源与合理性校验（门禁）

> **审查级别**：L1.5（门禁审查）— 检查校验报告本身是否合格，以及门禁结论取值是否与证据相符。
> **审查原则**：你是审查者，不是作者。必须重新打开校验报告与被校验产出逐项核对，不能凭记忆判断。
> **门禁语义**：本 checkpoint 审查的是「校验做得够不够实」，不是「需求写得好不好」。校验走过场比不校验更危险。

## 审查时需打开的文件
- 校验报告：`{WORKSPACE}/requirement/02-verify-report.md`
- 事实源表：`{WORKSPACE}/requirement/01-fact-source.md`
- 被校验产出：`{WORKSPACE}/requirement/01-modeling.md`、`01-intake.md`
- 头脑风暴：`{WORKSPACE}/requirement/00-brainstorm.md`
- 规范：`references/fact-source-standard.md`（§7 校验强度、§8 门禁结论、§9 产品版专属规则）

## 报告结构完整性
- [ ] 含 §0 校验范围（事实源条目总数、需求项数、启用维度、实际核验条目数与比例、降级判定结果）
- [ ] 含 §1 事实源真实性（表格，逐条列 FS-ID/级别/锚点/核验结果）
- [ ] 含 §2 无源断言检测（表格 + 数字型事实覆盖率）
- [ ] 含 §3 知识库引用真伪（表格 + 接口名专项统计）
- [ ] 含 §4 推断升格检测（表格 + approved 并存判定）
- [ ] 含 §5 历史需求只读合规（表格）
- [ ] 含 §6 内部一致性
- [ ] §3/§4/§5 均**实际执行**（产品版全维度启用，不得写「未启用」）
- [ ] 含 §7 待标记项汇总（表格：位置/应打标记/原因）
- [ ] 含 §8 门禁结论，且 `GATE_RESULT` 取值为 PASS/CONDITIONAL/FAIL 之一

## 校验强度合规（对照 fact-source-standard.md §7）
- [ ] 数字型事实核验比例为 **100%**（§0 与 §2 覆盖率一致，无遗漏）
- [ ] 关键业务规则核验比例为 **100%**
- [ ] **接口/消息名核验比例为 100%**（每个均经检索工具验证）
- [ ] 其余条目抽样比例 **≥ 30%**
- [ ] 每个需求项至少核验 1 条
- [ ] §0 声明的核验条目数与 §1 表格实际行数一致（无虚报）
- [ ] 执行模式为 agent（产品版不允许降级 inline）

## 知识库引用真伪检查（§3，产品版重点）
- [ ] `01-intake.md` §8 每条 F3 引用均已逐条验证，无抽样
- [ ] 每条引用的锚点精度达标（文件 + 章节/接口签名；只写目录名或只写文件名判不合格）
- [ ] 锚点存在性已用检索工具验证，报告附了检索命中位置
- [ ] 内容相符性已核对（该锚点确实描述了对照表所说的能力）
- [ ] 正文中所有「复用已有接口」声明的接口路径与方法均已在 `{CODE_KNOWLEDGE}` 中检索验证
- [ ] 检索不到的接口已判为臆造并标 `[事实源缺失]`（未被宽容处理为「待补充」）
- [ ] `[知识库待补充]` 与 `[事实源缺失]` 的区分口径正确（对照 §9.3）

## 推断升格检测检查（§4，产品版重点）
- [ ] 已打开 `00-brainstorm.md` 提取全部 `[AI推断]` 条目
- [ ] 已判定 `BRAINSTORM_STATUS: approved` 是否与未处理的 `[AI推断]` 并存
- [ ] 若并存 → `GATE_RESULT` 必须为 `FAIL`
- [ ] 每条推断结论在 intake/modeling 中的使用方式均已比对（是否被当作确定事实陈述）
- [ ] Phase D 的 `inferred_context` 未在无用户认领的情况下进入功能清单或验收口径
- [ ] 报告中对每条问题指明了「brainstorm 第 X 条推断 → modeling §Y」的对应关系

## 历史需求只读合规检查（§5，产品版）
- [ ] 已确认历史需求目录下无文件被修改或新增
- [ ] 已实际打开历史文档核对相似点（非仅凭目录名推定相似度）
- [ ] 已检测大段复制（连续 3 句以上重合判违规）
- [ ] `{BASE_DIR}` 未指向历史目录

## 证据可复核性（最易走过场，重点查）
- [ ] §1 中每个 ❌/⚠️ 结论都附了文件名 + 锚点 + 实际读到的原文片段
- [ ] §2 中每条无源断言都指明了正文位置（章节号）
- [ ] §6 中每个冲突项都指明了冲突的两处位置
- [ ] 报告中不存在无定位的「疑似」「可能」「大致」结论
- [ ] 抽查 §1 中任意 2 条标为 ✅ 的记录，按其锚点打开来源，确认核验结论成立

## 无源断言检测有效性
- [ ] §2 对正文中的功能点、接口/消息名、字段名、角色、外部系统名、数字六类均做了扫描
- [ ] 正文中出现的每一个数字都能在 §2 中找到对应判定（有源或已标记）
- [ ] 未出现「正文有数字但报告未提及」的情形

## 门禁结论正确性（对照 fact-source-standard.md §8 + §9）
- [ ] `GATE_RESULT` 取值与实际发现相符，未因「整体质量不错」而放宽
- [ ] 若存在 `[事实源缺失]` → 结论必须为 `FAIL`
- [ ] 若存在无 F1/F2 来源的数字型事实 → 结论必须为 `FAIL`
- [ ] 若存在未标记的无源断言 → 结论必须为 `FAIL`
- [ ] 若存在臆造的知识库引用或编造的接口名 → 结论必须为 `FAIL`
- [ ] 若 `approved` 与未处理 `[AI推断]` 并存 → 结论必须为 `FAIL`
- [ ] 若存在历史需求被修改或大段复制 → 结论必须为 `FAIL`
- [ ] 若结论为 `FAIL` → §8 列出了具体需修正项（指明步骤与位置）
- [ ] 若结论为 `PASS` → 确认存疑项 ≤ 2 且均已标记

## 只读合规
- [ ] `01-intake.md`、`01-modeling.md`、`00-brainstorm.md` 未被本步骤修改
- [ ] `{REQ}/requirement.md`（若已存在）未被本步骤修改
- [ ] 知识库任何路径（含 `{CUSTOM_KNOWLEDGE}/`）未被写入
- [ ] 历史需求目录下任何文件未被写入或修改
- [ ] 产出仅落在 `{WORKSPACE}/requirement/02-verify-report.md` 与状态报告

## 门禁处置确认（Scheduler）
- [ ] `PASS` / `CONDITIONAL` → 已准备进入 Step 3，§7 待标记项已交接
- [ ] `FAIL` → **已阻止**进入 Step 3，已按 step-02 §3 的回退目标表选择正确回退点
- [ ] 若 FAIL 原因为推断认领未处理 → 回退目标为 **Step 0 Phase F**（非 Step 1）
