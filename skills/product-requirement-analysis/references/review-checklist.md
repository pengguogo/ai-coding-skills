## 事实源与溯源评审

> 规则详见 `fact-source-standard.md`（产品版含 §9）。本段是评审视角的落点，不重述规则。

### 事实源登记
- [ ] 事实源表已归档到 `sources/fact-source.md`
- [ ] 每条记录的定位锚点可实际定位（非「材料里有」「知识库中提到」这类模糊表述）
- [ ] 级别标注（F1~F5）与实际来源相符，无虚标
- [ ] 每个需求项至少有 1 条关联事实源

### 数字型事实（重点）
- [ ] 正文中所有金额、时限、阈值、条数、超时、重试次数均有 F1/F2 来源或已标记
- [ ] 正文无裸数字（每个数字挂 `[FS-00X]` 或待确认标记）
- [ ] 同一口径的数字在不同需求项中无矛盾

### 知识库对照真实性（产品版重点）
- [ ] §8 对照表每条引用的锚点精确到文件 + 章节/接口签名
- [ ] 每条引用经检索验证确实存在，且内容与所述能力相符
- [ ] 所有「复用已有接口」的接口路径与方法在 code 知识库中可检索到
- [ ] `[知识库待补充]`（主题确实缺失）与 `[事实源缺失]`（引用臆造）区分正确

### 推断认领（产品版重点）
- [ ] `00-brainstorm.md` 中每条结论均标注了来源属性（`[用户确认]`/`[材料原文]`/`[知识库]`/`[AI推断]`）
- [ ] `BRAINSTORM_STATUS: approved` 时不存在未处理的 `[AI推断]` 条目
- [ ] 未经用户认领的推断未进入功能清单与验收口径
- [ ] 推断内容未在 intake/modeling 中被当作确定事实陈述

### 历史需求（产品版）
- [ ] §9 对照表标注的相似点经实际打开历史文档核对
- [ ] 无大段复制历史正文
- [ ] 历史需求目录未被修改

### 反臆造
- [ ] 接口/消息名均有出处；无出处的已写占位并标记
- [ ] 无「表外内容」——正文中的功能点、字段、角色、外部系统均在事实源表中登记
- [ ] AI 推断内容均已降级处理（标记或经用户认领）

### 门禁
- [ ] Step 2 门禁报告存在，`GATE_RESULT` 为 PASS 或 CONDITIONAL
- [ ] 全部 6 个校验维度均已实际执行（无「未启用」）
- [ ] 门禁报告中的待标记项已全部落到终稿
- [ ] 存疑/缺失/推断项已进入交付报告待确认项

## 评审最佳实践

1. **提前准备**：评审材料至少提前2天发送给参与人员
2. **控制时间**：单次评审会议不超过2小时
3. **聚焦问题**：关注需求和设计问题，避免陷入实现细节
4. **建设性反馈**：提供具体的改进建议，而非简单的批评
5. **记录完整**：详细记录评审意见和行动项
6. **跟踪闭环**：确保所有修改意见得到落实和验证
7. **持续改进**：定期回顾评审过程，优化评审效率
