# Step 1: 技能需求澄清

## 元信息

- execution-mode: inline

## 参数

- input: 用户自然语言描述的目标技能意图
- output: 结构化的技能需求规格清单

## 执行指令

### 1. 提取 5W1H 核心要素

向用户确认或从上下文中提取：

| 维度 | 问题 | 目标 |
|------|------|------|
| What | 这个技能要完成什么任务？ | 一句话概述核心功能 |
| Who | 谁使用这个技能？ | 用户角色（开发者/测试/运维/产品） |
| When | 什么场景下触发？ | 列举 3-5 个具体触发场景 |
| Where | 在什么环境中运行？ | 代码仓库/工作区/独立运行 |
| Why | 为什么需要这个技能（替代手动方案的痛点）？ | 核心价值主张 |
| How | 输入什么 → 产出什么？ | 输入物类型 × 输出物类型 |

### 2. 确定输入输出契约

- **输入**：用户提供什么（文件路径/代码片段/自然语言描述/URL）？
- **输出**：最终交付什么（文件类型/格式/位置）？
- **输出命名规则**：是否有动态部分（如场景名/日期）？

### 3. 定义触发词

列出中文 + 英文触发词，要求：
- 覆盖用户可能的自然表达方式
- 包含关键字变体（如"SQL 影响分析"和"数订正分析"）
- 不少于 3 个触发词

### 4. 识别关键约束

- 是否有**强依赖**（如必须读取某类文件、必须调用外部服务）？
- 是否有**硬性禁止**（如不可生成某类内容、不可访问某类资源）？
- 是否有**执行顺序依赖**（步骤 B 必须在步骤 A 之后）？

### 5. 输出规格清单

将以上内容汇总为：

```
## 技能需求规格

### 核心功能
{一句话概述}

### 用户角色
{角色}

### 触发场景
1. {场景1}
2. {场景2}
3. {场景3}

### 输入输出
- 输入：{输入物描述}
- 输出：{输出物描述}
- 命名规则：{命名模式}

### 触发词
{触发词1}、{触发词2}、{触发词3}

### 关键约束
1. {约束1}
2. {约束2}
```

## 产出

- 技能需求规格清单（5W1H + 输入输出 + 触发词 + 约束）
