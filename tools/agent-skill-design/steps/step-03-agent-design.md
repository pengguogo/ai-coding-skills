# Step 3: 代理与执行模式设计

## 元信息

- execution-mode: inline

## 参数

- input: Step 2 的 Phase/Step 划分方案
- output: 每个步骤的执行模式决策 + 子代理定义（若需要）

## 执行指令

### 1. 为每个步骤分配执行模式

对 Step 2 产出的每个步骤，决定执行模式：

| 执行模式 | 决策条件 | 适用场景 |
|----------|----------|----------|
| **inline** | 步骤逻辑简单、不产生大量中间输出、需要主流程上下文 | 解析/分析/组装/写入 |
| **subagent** | 步骤需要大量搜索/读取操作，或需要独立验证视角 | 代码扫描、全量搜索、交叉校验 |

**决策树**：

```
是否需要独立搜索/遍历大量文件？
├── 是 → subagent（选择合适的 agent 类型）
└── 否 → 是否需要验证前面步骤的产出（而非生成新内容）？
    ├── 是 → subagent（独立审查者视角更可靠）
    └── 否 → inline
```

### 2. 确定 agent 类型

如果步骤标记为 subagent，选择合适的 agent 类型：

| Agent 类型 | 能力 | 适用步骤 |
|------------|------|----------|
| `context-gatherer` | 搜索代码库、收集引用、定位事实源 | 代码追踪、数据收集、引用搜索 |
| `general-task-execution` | 执行通用任务、交叉校验、独立性验证 | 质量校验、完整性审查、事实源验证 |
| `explore-agent` | 综合分析研究、多源信息合成 | 信息调研、多源比对 |

### 3. 设计子代理指令

对每个 subagent 步骤，设计其指令模板（Prompt Template）：
- 输入参数：传递什么上下文给子代理
- 搜索范围：限定工作区路径或文件类型
- 输出格式：明确子代理应返回的结构化格式
- 约束条件：子代理的行为边界

子代理详细指令写入 `agents/{agent-name}.md`。

### 4. 输出执行模式分配表

```
## 执行模式分配

| 步骤 | 执行模式 | Agent 类型 | 原因 |
|------|----------|------------|------|
| Step 1 {名} | inline | - | {原因} |
| Step 2 {名} | subagent | context-gatherer | {原因} |
| Step 3 {名} | inline | - | {原因} |
| Step 4 {名} | subagent | general-task-execution | {原因} |

## 子代理定义

### Agent: {agent-name}
- 文件：agents/{agent-name}.md
- 输入：{输入来源}
- 输出：{输出格式}
- 核心任务：{任务描述}
```

## 产出

- 执行模式分配表
- 子代理定义列表（含指令要点）
