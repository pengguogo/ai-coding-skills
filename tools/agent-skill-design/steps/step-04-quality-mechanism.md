# Step 4: 质量机制设计

## 元信息

- execution-mode: inline

## 参数

- input: Step 2 的步骤划分 + Step 3 的执行模式分配
- output: 质量校验方案（校验点 + 清单 + 重试策略）

## 执行指令

### 1. 确定哪些步骤需要质量校验点

并非所有步骤都需要校验点。判断标准：

| 条件 | 是否需要校验点 |
|------|---------------|
| 步骤产出是**核心结论**（影响分析/风险评估） | ✅ 必须 |
| 步骤产出是**最终交付物** | ✅ 必须 |
| 步骤产出是**中间数据**（仅传递用） | ❌ 不需要 |
| 步骤是**格式转换**（无逻辑判断） | ❌ 不需要 |

**常见校验点位置**：
- 核心分析/计算步骤之后（验证结论正确性）
- 最终输出生成之前（验证数据完整性和一致性）
- 多条路径汇总点（验证汇聚逻辑）

### 2. 选择审查级别

| 级别 | 工作量 | 验证内容 | 何时选用 |
|------|--------|----------|----------|
| **L1 轻量** | 低 | 产出格式、必填字段、结构完整性 | 格式化/组装类步骤 |
| **L2 深度** | 中 | L1 + 事实源验证、引用真实性 | 分析/追踪类步骤 |
| **L3 全量** | 高 | L2 + 全量回归、边界条件、跨步骤一致性 | 最终交付前的终审 |

### 3. 设计校验清单

对每个校验点，列出具体检查项：

```markdown
### 校验点：Step N → Step N+1

#### 完整性检查
- [ ] 每个输入维度都有对应的输出
- [ ] 无遗漏的关键引用/数据源

#### 正确性检查
- [ ] 引用的事实源路径真实存在
- [ ] 结论与引用内容一致

#### 逻辑一致性检查
- [ ] 分级/分类标准一致
- [ ] 不存在自相矛盾的判断
```

校验清单写入 `checkpoints/step-0N-checkpoint.md`。

### 4. 设计重试策略

```markdown
## 重试策略

| 校验结果 | 动作 | 说明 |
|----------|------|------|
| 全部 ✅ | 进入下一步 | — |
| 存在 ❌ | 回到对应步骤修正，重新校验 | 最多重试 {N} 次 |
| 仅有 ⚠️ | 补充建议后进入下一步 | 不阻塞流程 |
| 超过重试上限 | 标注 `[需人工确认]` 后强制进入下一步 | 防止死循环 |
```

### 5. 输出质量机制方案

```
## 质量机制方案

### 校验点列表

| 序号 | 校验点（步骤间） | 审查级别 | 校验清单 |
|------|-----------------|----------|----------|
| Q1 | Step {N} → Step {N+1} | L2 | checkpoints/step-0N-checkpoint.md |
| Q2 | Step {M} → Step {M+1} | L3 | checkpoints/step-0M-checkpoint.md |

### 重试策略
- 最大重试次数：{N} 次
- 兜底策略：标注 [需人工确认] 后继续
```

## 产出

- 质量校验点列表（含审查级别）
- 校验清单文件（checkpoints/*.md）
- 重试策略定义
