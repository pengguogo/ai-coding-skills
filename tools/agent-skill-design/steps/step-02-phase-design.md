# Step 2: 阶段与步骤划分

## 元信息

- execution-mode: inline

## 参数

- input: Step 1 的技能需求规格清单
- output: Phase/Step 划分方案

## 执行指令

### 1. 识别自然阶段边界

按以下模式检查任务流程中是否存在自然断点：

| 阶段模式 | 判断标准 | 典型阶段名 |
|----------|----------|------------|
| 输入处理 | 需要解析/清洗/验证输入 | `analysis`、`parsing`、`intake` |
| 核心计算 | 执行主要分析/生成/转换逻辑 | `core`、`processing`、`generation` |
| 质量校验 | 需要独立审查/验证产出 | `verification`、`review`、`quality` |
| 输出生成 | 将结果组装为最终交付物 | `output`、`delivery`、`export` |

**原则**：阶段数建议 2-4 个，每个阶段内步骤数不超过 5 步。

### 2. 划分步骤

对每个阶段，将任务拆解为原子步骤：

**拆分规则**：
- 每个步骤应有**单一清晰职责**（只做一件事）
- 步骤间**输入输出明确传递**（不要让两个步骤并行依赖同一中间结果）
- 如果某个步骤需要搜索大量文件 → 考虑标为 subagent
- 如果某个步骤涉及最终文件写入 → 放在 output 阶段

**步骤编号**：按全局顺序编号，格式 `step-0N-{英文名}.md`

### 3. 设计步骤间的数据流

画出步骤间的输入输出关系：

```
[用户输入] → Step 1 → [中间产出A] → Step 2 → [中间产出B] → ...
```

确保每个步骤的 input 来自明确的产出源（上一步、用户输入、工作区文件）。

### 4. 输出 Phase/Step 划分方案

```
## Phase/Step 划分方案

### Phase: {阶段1}
- Step 1: {步骤名} → 产出: {产出描述}
- Step 2: {步骤名} → 产出: {产出描述}

### Phase: {阶段2}
- Step 3: {步骤名} → 产出: {产出描述}

### Phase: {阶段3}
- Step N: {步骤名} → 产出: {产出描述}

### 数据流
用户输入 → Step 1 → [产出A] → Step 2 → [产出B] → Step 3 → [产出C] → Step N → [最终交付物]
```

## 产出

- Phase/Step 划分方案（含数据流）
