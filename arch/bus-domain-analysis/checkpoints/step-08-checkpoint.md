# Checkpoint: Step 8 跨文档一致性

## 检查项

### 引用完整性
- [ ] arch 用例清单每个编号在 flow 目录有对应文件
- [ ] arch JS MAP 中的场景名与 flow 子目录名一致
- [ ] flow 页 .back-link `href` 正确指向 arch 页
- [ ] flow 页"关联功能时序图"链接 `href` 指向的 code sequence 文件存在
- [ ] code 页返回链接 `href` 指向的 flow 文件存在
- [ ] code↔用例多对多双向可达

### 内容一致性
- [ ] arch 用例编号、名称、核心说明 = flow 页 {UC_ID}、{UC_NAME}、说明
- [ ] arch 参与者列表覆盖所有 flow 页参与者
- [ ] arch 实体汇总覆盖所有 flow 页数据模型
- [ ] 同一实体在不同 flow 页的读/写模式无矛盾
- [ ] code 页分层链类名/方法/表名有代码依据；无据标 `[待确认]`，域外标 `[逻辑视图]`

### 格式一致性
- [ ] 公共资源相对路径可解析（arch/flow/code 各自前缀正确）
- [ ] Mermaid 初始化参数一致：`theme:'dark', securityLevel:'loose'`
- [ ] UC-{CODE}-{NN} 格式一致
- [ ] mermaid 块内无裸尖括号泛型（`<T>` → `[T]` 或转义）
- [ ] code 页多表落库步骤逐表补「表名：作用」（`<br/>` 换行，不用 Note）
- [ ] code 页共用返回链接：首个 `←`，其余 `back-sep |`

### 占位符收敛
- [ ] 统计全部产出中 `[待确认]`/`[逻辑视图]` 出现次数
- [ ] 逐项按 SKILL.md「占位符使用纪律」三类标准重新判定，能收敛则收敛
- [ ] 收敛后确认剩余占位符均为不可再收敛项（已执行最低检索仍未命中）
- [ ] 全文无"已扫描确认""已确认""经排查确认""已核实"等推导过程措辞
- [ ] 全文无猜测式框架/模块名称（所有功能归属可追溯到代码类名/包名/import）

### 重试策略
- 最多 2 次修正
- 超限标注 `[需人工确认]`
