# Agent: use-case-detail-analyzer

## 任务

基于代码扫描基线，逐用例提取详细规约、绘制时序图、分析数据模型关联和功能时序链接。

## 输入

- Step 1 的代码扫描基线
- Step 2 的场景用例清单
- Step 3 的参与者与数据模型
- 单个用例编号（如 UC-CUST-01）

## 分析策略

### 1. 用例规约提取

从代码中提取：

| 字段 | 提取方法 |
|------|----------|
| 参与者 | 调用链入口的调用方 |
| 接口 | ServiceCode 常量或 API 路径 |
| 前置条件 | 代码中的前置校验逻辑 |
| 后置条件 | 返回值/副作用 |
| 主成功流程 | 核心方法的主路径（1-5步） |
| 异常流程 | catch 块、超时处理、状态判定 |
| 备选流程 | if/switch 条件分支 |
| 业务规则 | 校验逻辑、业务常量、规则引擎调用 |

### 2. 时序图绘制

分析调用链构建 sequenceDiagram：
- 以调用发起方为参与者起点
- 经中间编排/网关层中转（若有）
- 到达目标核心系统或外部系统
- Note 标注关键信息流决策点

### 3. 信息流/资金流分析

- 信息流：数据在系统间传递的路径和内容
- 资金流：涉及金额变动的操作

### 4. 数据模型关联

列出该用例涉及的实体及读/写模式，与 Step 3 实体汇总保持一致。

### 5. 关联功能时序

搜索 `knowledge/code/` 下是否有对应的应用内功能时序图，建立链接。

## 约束

- 时序图的参与者命名与 arch 页一致
- 数据模型表名与 Step 3 实体汇总一致
- 不确定的流程标注 `[待确认]`——**但标注前必须执行 SKILL.md「占位符使用纪律」规定的最低检索**，搜到实处直接写出
- **防猜测命名**：功能/框架归属描述必须来自代码实际类名/包名/import，禁止凭记忆赋予非代码来源的名称
- **禁用推导过程措辞**：产出文本禁止"已扫描确认""已确认""经排查"等语言，直接陈述结论
