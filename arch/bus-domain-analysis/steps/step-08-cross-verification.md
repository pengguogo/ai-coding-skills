# Step 8: 跨文档一致性校验

## 元信息

- execution-mode: subagent
- agent: cross-verifier
- input: Step 5 的 `{domain}_arch.html` + Step 6 的所有 flow HTML + Step 7 的所有 code sequence HTML
- output: 校验报告

## 执行指令

### 1. 引用检查

- [ ] arch 用例清单中的每个编号，对应 flow 目录下存在同名文件
- [ ] arch JS MAP 场景名与实际子目录名一致
- [ ] flow 页 `.back-link` 指向的 `../{domain}_arch.html` 路径正确
- [ ] flow 页"关联功能时序图"链接指向的 `../../../code/...` 文件**存在**（Step 7 已生成）
- [ ] 每个 code sequence 页的返回链接（`../../../business/{domain}/{场景}/UC-*.html`）指向的 flow 文件存在
- [ ] code↔用例多对多关系双向可达（flow 关联了 code，code 也在返回链接列出该 flow）

### 2. 内容检查

- [ ] arch 用例清单的编号、名称、核心说明与 flow 页 {UC_ID}、{UC_NAME}、说明一致
- [ ] arch 参与者列表覆盖所有 flow 页的 {UC_PARTICIPANTS}
- [ ] arch 实体汇总与各 flow 页的数据模型串联无矛盾
- [ ] code 页分层链的类名/方法/表名有代码依据；无据处已标 `[待确认]`，实现不在工作区处已标 `[逻辑视图]`

### 3. 格式检查

- [ ] ocspec 根下、与 `knowledge/` 同级的 `{OCSPEC_ROOT}/common/` 下 case.css、mermaid.min.js 已落盘
- [ ] 公共资源引用前缀按页面深度正确：总览 `../../common/`、领域 `../../../common/`、flow `../../../../common/`、code `../../../../common/`
- [ ] Mermaid 初始化参数一致：`theme:'dark', securityLevel:'loose'`
- [ ] 用例编号格式一致：`UC-{DOMAIN_CODE}-{NN}`
- [ ] **mermaid 块内无裸尖括号泛型**（如 `BaseVo<T>`），已改 `[T]` 或转义，避免渲染破图
- [ ] code 页多表落库步骤已逐表补「表名：作用」（`<br/>` 换行，不用 Note）
- [ ] code 页共用返回链接：首个用 `←`，其余用 `<span class="back-sep">|</span>`

### 4. 占位符收敛复检

- [ ] 统计本领域全部产出中 `[待确认]`/`[逻辑视图]` 出现次数（`grep -c` 或等效）
- [ ] 逐项按 SKILL.md「占位符使用纪律」三类标准重新判定：
  - 类别 A：按交易码/表名/流程ID/事件类名执行检索，能命中 → 直接改写为实处（类名+模块）
  - 类别 B：确认为 TODO/空实现/代码不存在 → 改写为直接结论，去掉标签
  - 类别 C：确认为工作区外部系统 → 改写为"当前工作区外部边界"，去掉方括号标签
- [ ] 收敛后重新统计，确认不可再收敛的占位符数量，记入校验报告
- [ ] 确认全文无"已扫描确认""已确认""经排查确认""已核实"等推导过程措辞
- [ ] 确认无猜测式框架/模块名称（所有功能归属描述可追溯到代码类名/包名/import）
