# Step 2: 场景与用例识别

## 元信息

- execution-mode: inline
- input: Step 1 的代码扫描基线
- output: 场景分组 + 用例清单

## 执行指令

### 1. 按功能聚合场景

将 Step 1 的功能入口按**业务活动**聚合为场景。聚合规则：

- 同类业务流程的功能聚合为同一场景
- 场景数以 2-6 个为宜
- 每个场景下用例数为 2-8 个

示例（参考 customer 域）：
```
场景一：客户建档（CIF 创建/查询/变更）
场景二：合规筛查（名单筛查/风险评估/风险名单登记）
场景三：KYC 尽职调查（ECDD/会话检查/KYC 等级）
```

### 2. 为每个用例分配编号

编号规则：`UC-{DOMAIN_CODE}-{NN}`，NN 从 01 开始全局递增。

```
| 编号 | 用例名称 | 所属场景 | 主要参与者 | 核心说明 | 代码入口 |
|------|----------|----------|------------|----------|----------|
| UC-CUST-01 | CIF 客户创建 | 客户建档 | 编排引擎 | 在核心银行创建客户档案 | customer_open |
```

### 3. 设计用例图

用 Mermaid `flowchart LR` 绘制用例图，包含：
- 参与者（actor 样式：`fill:#1e2430,stroke:#34d399,color:#dde1ea`）
- 协作系统（sys 样式：`fill:#1e2430,stroke:#a78bfa,color:#dde1ea`）
- **外层领域边界 subgraph**（如 `subgraph B["贷款全生命周期 (loan)"]`），场景子图 `subgraph` 嵌套其中
- **每个用例是独立节点**（`U1(["贷款开立"])`），与用例清单 1:1 对应；**禁止用合并汇总节点**（如"开立/子账户/一次放款"），否则无法与清单逐条对应
- 粗箭头 `==>` 表示参与者发起场景/用例
- 语义化虚线：`-. 委托 .->`（委托协作系统）、`-. include .->`（用例包含）

结构示例：
```
flowchart LR
    APSI(["APSI 接入层"]):::actor
    FEE(["费用引擎"]):::sys
    subgraph B["贷款全生命周期 (loan)"]
      subgraph S1["① 开立与放款"]
        U1(["贷款开立"])
        U3(["一次开立发放"])
        U8(["开立费用处理"])
      end
    end
    APSI ==> S1
    U3 -. include .-> U8
    U8 -. 委托 .-> FEE
    classDef actor fill:#1e2430,stroke:#34d399,color:#dde1ea;
    classDef sys fill:#1e2430,stroke:#a78bfa,color:#dde1ea;
```


- 用例编号是否连续无遗漏
- 场景划分是否互斥且完备
