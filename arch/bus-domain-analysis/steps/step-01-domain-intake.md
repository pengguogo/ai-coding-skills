# Step 1: 领域识别与代码扫描

## 元信息

- execution-mode: subagent
- agent: code-scanner
- input: 用户在 Step 0.5 后明确指定的业务领域名称与待下钻场景（中文 + 可选的英文 domain 和 DOMAIN_CODE）
- output: 领域范围定义 + 代码扫描基线
- 前置门禁：对应 `{domain}_arch.html` 已生成，且用户明确确认进入该领域、该场景的用例/时序/code 下钻。

## 执行指令

### 1. 解析领域输入

从用户输入中提取：
- **领域中文名**：如"客户"、"账户"、"产品"
- **领域英文名（domain）**：如 `customer`、`account`、`product`（若用户未提供，自行确定）
- **DOMAIN_CODE**：4 字符大写编号前缀，如 `CUST`、`ACCT`、`PROD`（若用户未提供，按规则生成）
- **待下钻场景**：必须指定已在 `{domain}_arch.html` 的“正式场景目录”中列出的场景；未指定时只提示用户选择场景，禁止生成用例、时序或 code 页。

### 2. 确定代码扫描范围

根据领域名称，定位相关代码模块。扫描策略：

| 扫描维度 | 说明 |
|----------|------|
| Controller / Executor 类 | 按类名关键字符或包名匹配领域 |
| ServiceCode / API 入口 | 收集项目定义的 ServiceCode 或 API 路径 |
| 领域对象 / 实体类 | 收集 PO、DTO、Domain 对象 |
| MQ Consumer / Listener | 收集消息驱动入口 |
| 工作流 / BPMN | 收集工作流定义（若有） |

### 3. 扫描产出格式

```
## 领域定义
- 中文名：{领域中文}
- domain：{domain}
- DOMAIN_CODE：{CODE}

## 扫描范围
- 代码仓库/模块：[列表]
- 关键包路径：[列表]

## 扫描结果
### 功能入口清单
| 序号 | 功能入口（类名/方法） | 所属模块 | ServiceCode/API | 功能描述（从代码推断） |
|------|----------------------|----------|-----------------|----------------------|
| 1 | {类名.方法} | {模块} | {code} | {描述} |

### 涉及的数据实体
| 序号 | 实体/表名 | 所属模块 | 关键字段 | 说明 |
|------|----------|----------|----------|------|

### 关联外部系统
| 系统名 | 交互方式 | 关联入口 |
|--------|----------|----------|
```

### 4. 约束

- 只收集与指定领域相关的模块，避免扩大范围
- 每个入口必须标注信息来源（文件路径）
- 不确定的功能描述标注 `[待确认]`
