# Step 0.5：纵向业务领域总览批量生成（确认总览后执行）

## 元信息
- execution-mode: subagent（定向扫描）+ inline（生成）
- input: 已确认的 `business_arch.html`、`domain-backlog.md` 与全部非知识库应用仓库
- output: 每个纵向业务领域 1 份 `{domain}/{domain}_arch.html`
- 门禁：本步完成后必须停止，等待用户指定领域和正式场景，才可进入时序与代码下钻。

## 触发条件
仅当用户确认系统级总览后，或明确要求“生成纵向业务领域总览”时执行。本步覆盖系统总览 §4 中全部纵向业务生命周期领域；已有领域总览只补缺或按用户明确要求重建。

## 执行规则
1. 从系统总览和 `domain-backlog.md` 确定纵向领域清单、`domain`、`DOMAIN_CODE`、对应仓库和模块；逐领域定向扫描 Controller、交易码、Service、Job、Mapper、实体和配置。
2. 仅使用 `references/domain-overview-template.html` 生成 `{OCSPEC_ROOT}/knowledge/business/{domain}/{domain}_arch.html`。页面内容与章节结构必须对齐已确认的贷款领域总览：页面头和徽章、业务全景、参与者、用例图、用例清单、数据模型实体汇总、ER 图、页脚。
3. 正式场景按业务生命周期聚合；允许基于代码为用例目录分配 `UC-{DOMAIN_CODE}-{NN}` 编号。每个用例必须给出主要参与者、代码可确认的职责和 ServiceCode/代码入口；代码无法确认的交易码、外部系统、物理主键或运行状态必须标 `[待确认]`。
4. 此阶段只生成可审阅的领域总览：不得创建场景时序或 code 时序文件，不得在用例行添加跳转、点击行为或跳转图标；用例清单不得出现可点击样式。用户明确确认“领域 + 已列正式场景”后，才可生成下一层内容。
5. 必须生成用例图和 ER 图。用例图使用 `flowchart LR` 或满足页面布局的等价方向；数据模型优先输出 `erDiagram`。若未能确认物理表，改为“报文/逻辑映射图（非数据库 ER）”，并明确标注 `[待确认]`，不得虚构表、键或外键。
6. 场景标题是领域级正式标题，也是图 1 对应领域方块场景标签的唯一来源。更新领域总览后，必须同步回写 `business_arch.html` 图 1：链接存在、标题和顺序一致、方块内无场景或用例数量描述。
7. 同步更新 `domain-backlog.md`：场景/覆盖用例文字与领域总览一致，状态标注为“领域总览已生成；下钻待确认”。

## 完成后的强制停止
完成全部纵向领域总览后，向用户说明已生成的领域清单，并请求明确指定“哪个领域的哪个正式场景”进入下钻。未获确认不得执行 Step 1～Step 8。

## 校验
- 每个纵向领域均有且仅有一份 `{domain}_arch.html`；已有页面不重复创建。
- 每页均包含业务全景、参与者、用例图、用例清单、实体汇总、ER 图和页脚，章节与贷款领域总览一致。
- 页面没有下钻文件、代码时序引用、用例点击行为或跳转脚本。
- 图 1 中每个已链接纵向领域方块的场景标题、顺序均与对应详情页一致，且无数量性描述。
- 页面引用仓库级 `common/case.css`、`common/mermaid.min.js`；HTML 无诊断错误。
